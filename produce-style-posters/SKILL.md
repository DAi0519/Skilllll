# 风格海报生产

## 先明确职责与交付

在聊天中检查参考图片、提炼风格、编写双版提示词并调用可用图像生成工具。让平台承接版本、资产、关系、杂交实验和发文程序。不要为运行本流程擅自新增外部反推 API、API 密钥、付费服务或自动发布功能。

允许用户只上传参考图并给出品牌或主题。参考图尚未提供或无法查看像素时，索取图片，不从文件名假装完成反推。明确当前阶段与版本，避免把“文本检查通过”“实际生图通过”“用户审核通过”混成一个状态。

## 1. 看图并提炼可迁移 DNA

逐张查看原始图像，记录构图、字体构造、文字层级、颜色关系与底色、形状语法、主体/辅助物件、材质、叠压、空间密度与留白。区分可见事实和推断，不声称知道原始作者的模型或提示词。

多图时提取共同规则，列出冲突与可选变体。不要平均掉不同风格；无法合理确定主次时只问必要选择。将参考图品牌、具体动物道具、现成文案和单一配色与视觉语法分开，不把它们全部锁进新风格。

将比例作为单次生成参数。通用提示词不固定 3:4、16:9 或其他画幅；任务指定时严格遵守，未指定时说明本次选择但不要污染通用规则。底色根据原图判断，不把纸感自动写成旧纸黄。对于近白参考，明确低黄度、轻微暖灰和禁止整体黄滤镜。

## 2. 生成同源双版本

读取 [提示词与验证规范](references/prompt-validation.md)。先建立一个带版本号的风格记录，再从同一记录产生：

- 生产 JSON：可解析、字段清晰，包含视觉约束、文案生成规则、输入契约与禁忌；用于实际生产。
- 分享自然语言：真正连贯、可直接复制的中文段落；按需提供英文。保留关键约束，不逐字段堆砌 JSON，不藏额外补丁；视觉语言接近生产版即可，不保证像素或构图一致。

两版均支持仅输入品牌/主题，自动生成主标题、主题短句、简短辅助信息三层文案；保持易读与适量。文案必须依据主题，不凭空编活动日期、地址、折扣、价格、联名、官方关系或获奖信息。用户提供准确文案时原样使用；仅在完整度必需时询问，不让普通主题迁移依赖用户补齐文案。

## 3. 先实际验证，再批量

冻结两版原文和具体版本，保存实际提交给工具的完整输入、参考图使用情况、模型/工具可见标识、时间和输出。每次影响效果的改版都重新生成；两版都要验证。不得把旧图、mock、拼图、文字评审或 JSON 解析通过称为本轮实际生图验证。

最小输入测试只使用冻结提示词加品牌/主题；禁用参考图、额外主题定制文案、隐藏风格补充、之前成功示例。工具必须具备干净输入能力才可称“独立最小输入测试”；若工具隐式上下文无法隔离，注明限制，不夸大可复现性。默认选至少一个品牌和一个不同类主题，逐版检查文案三层、风格、底色、布局、主体相关性、文字可读性和无编造事实。两版分别记录失败和回调；修订后新建版本再测。

工具不可用、额度/权限受阻时保留未验证状态并说明准确阻塞，不以手工做图代替生图验证。保存真实输出并让用户审核；未经审核不得写“用户通过”。

## 4. 生产候选与审核包

先让用户审核小样与两版，再按明确数量和范围生产。若用户选择完整 22 张方案：提出 10 个适配品牌、10 个活动/主题候选，确认选题后再生成，加 1 张“设计提示词分享”首图与 1 张极简“DESIGN HAPPY”尾图。不要默认先生成 22 张再发现提示词不可用；不要编造活动的真实举办信息。

将 22 张分别编号交付，保留独立原图；联系表只辅助审核，不替代单图。记录每张用哪版提示词、哪个主题、哪个实际输入、是否候选/替代/旧证据。首尾的专门版式明确作为衍生设计，不假称通用最小输入结果。

提供两份可复制提示词文件，以及流程经验文档：目标、输入、版本、实际测试、失败与修改、限制、最终选择、可复用经验。只写有证据的经验，不把一轮偶然成功写成模型保证。

## 5. 归档、杂交与发文衔接

读取 [集成适配](references/integrations.md)，运行时核验用户项目和 Notion 当前结构。工作台 production v1 升级已撤回；[平台 v1 契约](references/production-v1.md)仅保留为历史可选资料，不可假设对应 CLI 或 HTTP 路由存在，不主动重建。默认继续聊天看图、双版提示词、真实生图及文件交付；Notion 归档与原杂交、发文程序必须重新核验当前接口后再衔接。优先复用现有个体库、实验库及关系字段；发现不匹配先提供映射，保留历史评分与记录，不覆盖旧版本。

归档参考资产、DNA、两版提示词、完整生成输入、验证证据、审核状态、候选来源与关联 ID。每次修订保留父版本。杂交时记录父本版本、继承/改变维度、权重的含义（若有）、子代提示词与独立新验证；不把混合即视为进步，不覆盖父本评分。

需要用户电脑上的程序时，通过受支持的本地执行子任务访问，先核验连接与目标项目，禁止从聊天云环境假装直接访问 Mac。按已核验导入契约交付文件，不猜 CLI、端口、JSON schema 或 API。调用现有发文程序生成标题、正文、标签与图序草稿；输出中说明哪些图来自生产 JSON，公开分享的是自然语言版且只追求近似风格。涉及用户口吻的文案先遵循可用写作风格规范。

发文流程止于可审核草稿；用户未明确授权具体发布时不发布。Notion 写入须在用户授权的空间/数据库内，不新扩展访问权限；目标不明则先问。接入失败继续准备本地交付包并报告未同步状态，不伪造 URL 或成功回执。

## 6. 完成前核对

使用 scripts/validate_evidence.py 检查验证记录；该脚本仅核验结构、文件和输入哈希，不判断图像质量或用户批准真实性。人工检查图片和批准来源，分别报告文本/真实生图/用户审核/归档/发文草稿状态。链接到真实已保存资产与已核验记录，明确仍缺失的环节。
